## 2. 比赛作品要求（第 (2) 条）

| 要求 | 实现情况 | 证据 |
| --- | --- | --- |
| 用户信息保护 | 密码 BCrypt；刷新令牌只存哈希；可删除账号与行程 | 《系统说明书》第 8 节 |
| 网络通信安全 | 全部走 HTTPS 就绪的 REST 接口；release 包禁明文且无 HTTP 回退；令牌走系统 Keystore | `lib/core/network/`、`lib/core/storage/` |
| 数据存储安全 | 服务端密钥只读环境变量；APK 内无任何第三方密钥 | `scripts/local.env`（git-ignored）、`.env.example` |
| 智能算法合规 | 行程生成的结果由后端校验（开放时间 / 时间冲突 / 换乘余量 / 预算 / 天气 / 强度）；LLM 不承诺购票与安全 | `ai/TripPlanValidator.java`、`service/PlanDates.java` |
| 第三方来源透明 | 每条数据带 `source` 与 `dataStatus`，界面上分"实时 / 缓存 / 系统资料 / 演示 / 已过期" | `lib/core/widgets/data_status_*.dart` |
| 图片版权 | 配图合规判定收敛在 `PoiImageAudit`（缺图 / 占位图 / 来源未登记 / 已登记），管理台出"待处理 N"面板与筛选、逐条列待办，详情页对占位图明确标注"非河南实景"；人工作业见《配图作业单》 | `common/PoiImageAudit.java`、`admin/src/views/PoisView.vue`、`screens/additional_screens.dart`、`docs/DELIVERY/配图作业单.md` |

## 6. 应用推广价值

| 维度 | 说明 |
| --- | --- |
| 场景真实 | 河南是文旅大省，"一至三日自由行"是最主流的出行形态 |
| 可复制 | 三条走廊是内容工作，走廊模板可平移到其他省份 |
| 成本可控 | 天气用免费的 Open-Meteo；LLM 可四家切换压价；底图 12 小时缓存省配额 |
| 有落地抓手 | 内容由运营台维护，不需要改代码就能加景点、换配图、调提示词 |
| 有商业想象空间 | 门票比价、酒店、文创、地方文旅合作都已有端口预留 |
