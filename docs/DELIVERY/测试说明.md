`planner_conditions_test.dart` 覆盖的正是历次真机反馈回归：

- 中文日期（同一天在日历、表单、列表里只有一种写法；相对日只给三天内标签）；
- 同行人数排在同一行；
- 行程天数改为可输入步进控件且当场夹回；
- 兴趣与体力各自带自定义入口，添加后不破坏布局；
- 交通方式展开态与收起态联动；
- 出发地 / 目的地交换动画后文字仍在裁剪框内（T14 回归）；
- 出发地与目的地选成同城时自动对调；
- 城市选择器可搜索、可直接输入；
- 历史行程列出、打开、重命名、二次确认后删除。

`trip_navigation_test.dart` 是用户报的"卡在行程详情里出不去"那条缺陷的回归用例：

- 行程相关页面用的是产品自己的 `AppBackButton`，**不再依赖 `AppBar` 的自动 leading**
  （后者只在"这条路由下面还有活动路由"时才渲染，属于静默失效）；
- 两条入口（我的 → 我的行程、行程 → 查看历史行程）都要求"每层都能退、退到底底部导航还在"；
- 连点两下入口只压一层历史页，按一次返回就直接回到行程首页。

`discover_feed_test.dart` 钉住首页信息流的三个不变量：

- **一次只取 6 张**：进页面只发一次 `page=1&size=6`，不多取；
- **滚到底才续下一页**：滑到距底部 480px 内才请求 `page=2`，拿到 `hasMore=false` 后不再发请求；
- **回到初始态**：切到行程 Tab 再切回发现页，请求序列变成 `1 → 2 → 1`，不会停在翻到一半的位置。

"查看更多"进入的"河南景点"整页用**自己的一套分页**（每页 12），与首页信息流互不干扰。


> **写组件测试时的一个坑（已经踩过一次）**：`testWidgets` 的测试体跑在假时钟里。
> `await session.read()`、`await container.read(provider.future)` 这类"真异步"的 await
> 会让整条用例**永远挂住，连测试超时都不触发**（超时计时器本身也在假时钟上）。
> 正确做法：驱动 provider 状态用 `tester.pump(step)` 推固定帧数，
> 真正需要真异步的读放进 `tester.runAsync()`。详见 `test/screens/account_signin_test.dart` 顶部注释。

## 5. 安全测试

| 项 | 期望结果 |
| --- | --- |
| 未登录访问受保护接口 | 401，不返回业务数据 |
| 普通用户访问 `/api/admin/**` | 403 |
| 用别人的行程 ID 读 / 改 / 删 | 404 或 403，且不泄露是否存在 |
| 令牌过期 | 401，客户端自动刷新一次后仍失败则清会话 |
| 密码存储 | 数据库里只有 BCrypt 哈希 |
| 日志内容 | 不出现令牌、密码、AK、完整敏感请求体 |
| APK 内容 | 解包后无第三方 AK / API Key |
| 上传接口 | 只接受图片类型，超限与超大尺寸被拒；文件名不参与路径拼接 |
| 分享页 | 可设有效期、可隐藏预算、可关闭；不含账号与个人信息 |
| 验证码 | 只存哈希、有有效期、有限流与尝试次数上限 |
| SQL / XSS | 参数化查询；分享页与服务端渲染内容转义 |
| 接口限流 | 超额度返回 429 且带 `Retry-After`；不同主体互不影响；读接口不被写接口的额度牵连 |
| 限流主体识别 | 公网直连时**不采信**客户端自带的 `X-Forwarded-For`（否则伪造该头即可绕过限流） |
| 外部工具配额 | 额度用尽时熔断且**不消耗上游**；只对真正调用第三方接口的工具生效，本地内容库不受限 |
| 请求体积 | 非上传请求超过 1 MB 返回 413；上传走 multipart，由各自的业务上限约束 |
| 越权删除评论 | 删除他人评论返回 404 而非 403（后者会暴露该 id 是否存在） |
| APK 发布校验 | 正式通道比对签名证书白名单；调试通道只验签名有效性，不比对白名单 |

### 5.1 限流与配额的实测记录

以下是在真实部署环境上跑出的结果（非模拟）：

```text
连续 12 次错误口令登录（auth 桶 = 10 次 / 60 秒）
→ 401 ×10，随后 429 429
→ {"code":"RATE_LIMITED","message":"请求过于频繁，请 60 秒后再试","bucket":"auth"}

同一时刻读接口不受影响：GET /api/pois → 200
未带管理员身份访问限流配置接口 → 401

POST /api/feedback，body 约 2 MB（JSON）
→ 413 {"code":"PAYLOAD_TOO_LARGE","message":"请求内容过大"}

GET /api/admin/security/limits（管理员身份）
→ activeWindows=4；weather 0/500、route 0/300、rail 0/300
```

`used = 0` 是正确结果：前一天的工具调用不计入今天（按 Asia/Shanghai 自然日切分）。

## 7. 已知未覆盖

| 项 | 说明 |
| --- | --- |
| 真机自动化 | 目前是"自动化三档布局 + 人工真机目视"，没有接入 Appium / integration_test |
| 弱网注入 | 只做了"断网"这一档，没有做丢包 / 高延迟 / 半开连接 |
| 并发与压测 | 未做，首版定位是单机演示（比赛现场并发量极小） |
| 无障碍朗读 | 只做到语义标签与对比度，未做 TalkBack 全流程走查 |
| 12306 中转 | `searchTransfer` 已接入规划工具链；解析层与预算下限已有单元测试，真实中转结果仍受 12306 外部可用性影响 |
| 邮箱验证 | SMTP 属首版预留能力，没有验证码发送 / 校验的端到端用例 |
| 消息中心 | 本机说明页：已覆盖未读增减与已读标记，尚未接服务端推送与跨设备已读同步 |
| 足迹里程 | 只验证聚合口径；某条路线工具没返回距离时"不计入"这一支靠单元测试覆盖，没有真实站点数据对照 |
| 限流的多实例一致性 | 限流计数与运行时设置缓存在进程内存中，**单实例部署下正确**；多实例时每个实例各限一份，实际放行量会翻倍。要水平扩展需换成 Redis（见 `docs/SECURITY_AUDIT.md`） |
| 数据库备份 | 未做自动备份与恢复演练；MySQL 在 Docker 卷里，误删数据卷会连同用户与行程一起丢失 |
| 外部监控告警 | 只有容器 healthcheck 自愈，没有磁盘 / 内存 / 重启次数告警，异常需要人工查看运营台 |
| 分块传输的体积绕过 | 体积护栏读 `Content-Length`，chunked 请求没有该头，由 Tomcat 自身的上限兜底 |
| 社区评论的通知细则 | 评论与回复会发站内消息，点赞不发（避免高频打扰） |
