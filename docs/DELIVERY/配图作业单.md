> 这是 P0 里唯一**必须人工完成**的活：图得有人去拿、去授权。
> 这份作业单把"拿什么图、放多大、登记什么、怎么算完成"写死，
> 你只需要照着填，不用再回来问规则。

内容库现有 **30 条已上架景点**，且**每条都有配图、版权字段也都非空**。
但"字段非空"不等于"授权可用"，实际分两类：

| 类别 | 条数 | 配图来源 | 版权字段 | 结论 |
| --- | --- | --- | --- | --- |
| **A 类：已落地** | 4 | 上传到本服务 `/media/`，由我们自己托管 | 写的是"河南实拍授权图" | 可用，但**来源链接建议补成可核验的出处** |
| **B 类：待处理** | 26 | 外链到百度 / 抖音 / 百度 BOS 等 CDN | 仅"摄影师""摄影集"这类占位文本 | **不构成授权记录**，见下 |

A 类景点（三条示范走廊的核心）：龙门石窟、嵩山少林、云台山、清明上河园。

> A 类的图已经托管在自己服务器上，不依赖外链，**这一点是对的**；
> 但 `sourceUrl` 目前填的是"摄影集"三个字，不是可点开的出处。
> 评委若追问"授权从哪来"，这三个字答不了。建议补成具体来源
> （摄影师授权书编号 / 图库订单号 / 官网公示页链接）。

### 1.1 B 类为什么必须处理

**版权角度。** 这 26 条的图片是搜索结果图，`imageCredit` 填的是"摄影师""摄影集"，
既没有具体权利人，也没有授权范围。它**不是授权记录**，只是把字段填满了。

**稳定性角度。** 外链指向别人的 CDN，随时可能失效：

- 部分抖音链接带签名与过期时间（`x-expires=`）；
- 部分百度 BOS 链接带 `authorization=bce-auth-v1/...` 的临时凭证；
- 百度图片 CDN 通常禁止站外引用。

一旦失效，客户端只会显示占位图——**演示当天才发现是最坏的情况**。

### 1.2 一个需要知道的口径问题

管理台的配图审计（`PoiImageAudit`）判定标准是"版权说明是否非空"。
因此上面 26 条目前显示为 **`REGISTERED`（已登记）**，管理台不会把它们列为待办。

这不是审计逻辑写错了，而是**它只能判断"字段填没填"，判断不了"授权是否成立"**。
本作业单的作用就是补上这层人工判断。

> 建议：公开演示前把这 26 条逐条替换为 A 类做法（可授权的图 → 上传到本服务 → 填写真实的授权说明）；
> 来不及替换的，至少**不要放进演示路径**，并在管理台把版权说明改成
> "图片版权未核验，仅内部演示占位"，不要用"摄影师"这种看起来像已授权的措辞。

下表覆盖三条示范走廊的核心景点（**不是全部 30 条内容库**；其余景点按同一标准判断，

## 3. 图片技术规格

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 格式 | JPEG / PNG / GIF | 服务端只接受这三种，其余直接拒绝 |
| 单张体积 | ≤ 8 MB | 超过会被拒（请求体上限 12 MB） |
| 长边像素 | ≤ 6000 px | 超过会被拒 |
| 建议尺寸 | **横图，1800×1200 左右（3:2）** | 客户端按固定高度居中裁切（BoxFit.cover），横图最不容易裁掉主体 |
| 构图 | 主体放在画面中间 2/3 区域内 | 手机竖屏与大屏卡片都会裁切上下或左右 |
| 色调 | 自然、不要重滤镜，不要加文字水印 | 卡片上要叠加标题，重色块与文字会打架 |
| 命名 | 用景点名，例如 `longmen-01.jpg` | 上传后服务端会重命名，但你自己挑图时不容易搞混 |

> 别用竖图当主图：客户端卡片是横向的，竖图会被裁掉大半。

## 4. 上传与登记步骤

1. 打开管理台 → 「景点管理」；
2. 点顶部「待处理 N」，只看还没闭环的景点；
3. 点某一行「编辑」，在「景点主图」处点 **上传本地图片**，选好文件；
4. 在同一条抽屉里填：
   - **图片版权 / 授权说明**（必填，例如 `摄影：张三，已获本人授权，仅限本项目展示`）；
   - **数据来源链接**（建议填，景区官网或文旅厅公示页）；
5. 点「保存」——列表里的配图状态会立刻重新判定，变成「已登记」。

抽屉里会实时显示这一条**当前差什么**，保存后状态自动刷新，不需要额外点一次"重新审计"。

## 5. 版权与合规要求

比赛会看"合规意识"，所以这一节不是走过场。

### 可以用的来源

| 来源 | 登记时怎么写 |
| --- | --- |
| 自己拍 / 团队成员拍 | `摄影：本团队（原创拍摄）` |
| 摄影师授权 | `摄影：姓名，已获本人授权，仅限本项目展示` |
| 景区官方图（明确允许使用） | `来源：XX 景区官网，已获授权使用` |
| 政府 / 文旅部门公开发布 | `来源：XX 市文化广电和旅游局公示页` |
| CC0 / 公有领域 | `来源：XXX，CC0 公有领域` |

### 不要用

- 百度图片、小红书、马蜂窝、携程等平台的用户照片（没有授权就是没有授权）；
- 带他人水印或平台水印的图；
- 来源不明、说不清出处的图；
- AI 生成的"河南实景图"——除非在版权说明里明确写 `AI 生成示意图，非实拍`，
  并且**不要把它当成景区实拍展示**。

### 一句话模板

> `来源：<在哪里拿到的>，授权：<怎么授权的>，使用范围：本项目比赛演示`

## 6. 验收标准

- 管理台「景点管理」页顶部显示 **待处理 0**；
- 每个景点详情抽屉里状态是「已登记」；
- **且**该条配图是上传到本服务 `/media/` 的托管图，而不是外链到第三方 CDN；
- **且**版权说明能回答"来源 / 授权 / 使用范围"三问，而不是"摄影师"这类占位文本；
- APK 景点详情页的「图片来源」一节只剩出处文字，**不再出现"占位示例图"提示**；
- 断网 / 首次启动走的**内置兜底**景点仍旧标着占位图 —— 这是刻意的：
  兜底素材本来就是示例图，不能因为判断逻辑拿不到就变成"未标注"。

> 前两条是机器判定，后两条只能人工看。**「待处理 0」不等于配图合规**——
> 见 1.2 与 7.1。

## 7. 判定规则（写在代码里的那一份）

管理台与 APK 用的是同一套判定，规则在
`server/src/main/java/com/yujian/travel/common/PoiImageAudit.java`：

| 状态 | 触发条件 | 界面 |
| --- | --- | --- |
| 缺配图 | 没有图片地址 | 红标，待办「上传有授权的河南实景图」 |
| 占位示例图 | 图片域名是 Unsplash / Pexels / Pixabay，**或**版权说明里出现"占位 / 示例素材 / 非河南实景 / 待替换" | 红标，待办「替换为有授权的河南实景图」 |
| 来源未登记 | 有图，但版权说明与来源链接都为空 | 黄标，待办「登记图片版权 / 授权说明」 |
| 已登记 | 有图 **且** 版权说明非空 | 绿标，可以交付 |

两个刻意的设计：

1. **域名命中优先于文字说明**：一段写得很漂亮的授权说明，也改变不了
  这张图来自 Unsplash 这个事实；
2. **来源链接缺失不算待办**：待办清单里放"可以不做的事"，列表就永远清不空。

### 7.1 当前判定覆盖不到的一类：第三方 CDN 外链

判定表的域名清单目前只列了 Unsplash / Pexels / Pixabay。实际库里有 26 条图片
外链到百度图片、抖音、百度 BOS 等 CDN，因为域名不在清单里、版权说明又非空，
所以被判定为「已登记」。

**补法有两种，任选其一：**

| 做法 | 说明 |
| --- | --- |
| 收紧判定（推荐） | 在 `PoiImageAudit` 的外部域名清单里补上 `baidu.com`、`bdstatic.com`、`bcebos.com`、`douyinpic.com` 等，命中的一律判为「来源未登记」，让它们出现在待办里 |
| 人工核对 | 保留现状，但按本作业单 1.1 逐条替换；替换完成前不把对应景点放进演示路径 |

收紧判定的代价是所有存量外链都会变成待办 —— 这正是它应该有的样子：
**待办为 0 才代表配图真的能用。**
