## 3. 图片技术规格

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 格式 | JPEG / PNG / GIF | 服务端只接受这三种，其余直接拒绝 |
| 单张体积 | ≤ 8 MB | 超过会被拒（请求体上限 12 MB） |
| 长边像素 | ≤ 6000 px | 超过会被拒 |
| 建议尺寸 | **横图，1800×1200 左右（3:2）** | 客户端按固定高度居中裁切（BoxFit.cover），横图最不容易裁掉主体 |
| 构图 | 主体放在画面中间 2/3 区域内 | 手机竖屏与大屏卡片都会裁切上下或左右 |
| 色调 | 自然、不要重滤镜，不要加文字水印 | 卡片上要叠加标题，重色块与文字会打架 |
| 命名 | 用景点名，例如 `longmen-01.jpg` | 上传后服务端会重命名，但你自己挑图时不容易搞混 |

> 别用竖图当主图：客户端卡片是横向的，竖图会被裁掉大半。

## 4. 上传与登记步骤

1. 打开管理台 → 「景点管理」；
2. 点顶部「待处理 N」，只看还没闭环的景点；
3. 点某一行「编辑」，在「景点主图」处点 **上传本地图片**，选好文件；
4. 在同一条抽屉里填：
   - **图片版权 / 授权说明**（必填，例如 `摄影：张三，已获本人授权，仅限本项目展示`）；
   - **数据来源链接**（建议填，景区官网或文旅厅公示页）；
5. 点「保存」——列表里的配图状态会立刻重新判定，变成「已登记」。

抽屉里会实时显示这一条**当前差什么**，保存后状态自动刷新，不需要额外点一次"重新审计"。

## 5. 版权与合规要求

比赛会看"合规意识"，所以这一节不是走过场。

### 可以用的来源

| 来源 | 登记时怎么写 |
| --- | --- |
| 自己拍 / 团队成员拍 | `摄影：本团队（原创拍摄）` |
| 摄影师授权 | `摄影：姓名，已获本人授权，仅限本项目展示` |
| 景区官方图（明确允许使用） | `来源：XX 景区官网，已获授权使用` |
| 政府 / 文旅部门公开发布 | `来源：XX 市文化广电和旅游局公示页` |
| CC0 / 公有领域 | `来源：XXX，CC0 公有领域` |

### 不要用

- 百度图片、小红书、马蜂窝、携程等平台的用户照片（没有授权就是没有授权）；
- 带他人水印或平台水印的图；
- 来源不明、说不清出处的图；
- AI 生成的"河南实景图"——除非在版权说明里明确写 `AI 生成示意图，非实拍`，
  并且**不要把它当成景区实拍展示**。

### 一句话模板

> `来源：<在哪里拿到的>，授权：<怎么授权的>，使用范围：本项目比赛演示`

## 6. 验收标准

- 管理台「景点管理」页顶部显示 **待处理 0**；
- 每个景点详情抽屉里状态是「已登记」；
- APK 景点详情页的「图片来源」一节只剩出处文字，**不再出现"占位示例图"提示**；
- 断网 / 首次启动走的**内置兜底**景点仍旧标着占位图 —— 这是刻意的：
  兜底素材本来就是示例图，不能因为判断逻辑拿不到就变成"未标注"。

## 7. 判定规则（写在代码里的那一份）

管理台与 APK 用的是同一套判定，规则在
`server/src/main/java/com/yujian/travel/common/PoiImageAudit.java`：

| 状态 | 触发条件 | 界面 |
| --- | --- | --- |
| 缺配图 | 没有图片地址 | 红标，待办「上传有授权的河南实景图」 |
| 占位示例图 | 图片域名是 Unsplash / Pexels / Pixabay，**或**版权说明里出现"占位 / 示例素材 / 非河南实景 / 待替换" | 红标，待办「替换为有授权的河南实景图」 |
| 来源未登记 | 有图，但版权说明与来源链接都为空 | 黄标，待办「登记图片版权 / 授权说明」 |
| 已登记 | 有图 **且** 版权说明非空 | 绿标，可以交付 |

两个刻意的设计：

1. **域名命中优先于文字说明**：一段写得很漂亮的授权说明，也改变不了
   这张图来自 Unsplash 这个事实；
2. **来源链接缺失不算待办**：待办清单里放"可以不做的事"，列表就永远清不空。
