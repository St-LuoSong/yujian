# 社区板块实施计划

> 定位：用户分享自己的河南旅行时光，形成可浏览、可审核、可举报的旅记社区。
> 首版目标不是做完整社交平台，而是把“行程 → 旅记 → 公开浏览 → 审核”闭环做扎实。

## 阶段一：后端底座（已完成，2026-10-02）

- `community_post`：旅记主体、行程关联、公开范围、审核状态；
- `community_post_image`：旅记图片 URL 与排序；
- `community_like`：用户点赞；
- `community_report`：用户举报；
- 发布、浏览、详情、编辑、删除；
- 点赞 / 取消点赞；
- 举报与管理员审核；
- 分页、城市/标签筛选；
- 单元测试与安全边界：后端 108 项测试通过。

## 阶段二：Flutter 浏览体验（已完成，2026-10-02）

- 底部导航或发现页入口；
- 社区信息流：分页、城市/主题筛选；
- 旅记详情：图片、正文、行程摘要、点赞、举报；
- 未登录时引导登录，但不阻断浏览；
- 加载、空态、错误状态；社区信息流首次进入才加载，避免后台无意义请求。

## 阶段三：Flutter 发布流程（已完成，2026-10-02）

- 从已保存行程创建旅记；
- 标题、正文、城市、标签、图片；
- 公开 / 仅自己可见；
- 设置预算、备注和个人信息脱敏；
- 提交后展示“审核中 / 已通过 / 已驳回”。

已实现：从本人已保存行程发布、标题/正文/城市/标签、公开范围、1—9 张图片、
系统相册选择、服务端重编码去 EXIF、提交后进入审核。

## 阶段四：管理台审核

- 待审核列表；
- 通过、驳回、下架、恢复；
- 举报列表与处理；
- 操作日志；
- 内容来源和发布时间。

## 阶段五：安全、隐私与质量

- 图片 EXIF 清理，避免精确位置泄露；
- 文本长度、图片数量、发布频率限制；
- 举报、封禁与内容删除；
- 公开内容不包含预算、邮箱、精确位置；
- 关键词过滤与人工审核组合；
- Flutter / 后端 / 管理台三端测试和真机验收。

## 首版暂不做

- 评论与回复；
- 关注、粉丝、私信；
- 实时聊天；
- 算法推荐；
- 打赏、商家入驻；
- 精确轨迹公开。
