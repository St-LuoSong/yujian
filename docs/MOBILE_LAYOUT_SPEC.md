# APK 移动端分辨率与响应式布局规范

> 版本：v0.1 / 2026-10-01
> 目标：保证《豫见智旅》在 Android 10+ 常见中端手机上可读、不溢出、可触控、可恢复。

## 1. 先统一“分辨率”和“布局单位”

Flutter 页面使用 **logical pixels（dp 逻辑像素）**，不是直接按物理像素写死。比如 1080×2400 的手机在系统 density=3 时，Flutter 逻辑宽度约为 360dp。设计稿必须标注 dp，不标注截图物理像素。

验收目标不是覆盖某一款手机，而是覆盖一个范围：

| 档位 | 参考逻辑尺寸 | 常见物理分辨率示例 | 用途 |
| --- | ---: | --- | --- |
| S 小屏 | 360 × 800dp | 1080 × 2400 @3 | 最低布局基线，必须不横向溢出 |
| M 主验收 | 390 × 844dp | 1170 × 2532 @3 | iPhone 14/15 级别的内容比例，作为视觉主稿 |
| L 宽屏 | 412 × 915dp | 1080/1440 × 2400 级别 | Android 大屏/高密度设备，检查留白和长标题 |
| Fold/平板 | 600dp+ 宽 | 折叠展开或平板 | 首版不做双栏业务布局，只保持单栏最大内容宽度 |

**硬性基线：**`360dp` 宽、`800dp` 高的 portrait 页面必须通过。`390dp × 844dp` 作为比赛截图和主视觉验收尺寸。`412dp` 用于检查不会把内容拉得松散或产生异常空白。

## 2. 设备方向与系统窗口

首版固定 portrait（竖屏）体验，不做横屏业务布局。原因是游客单手浏览、输入和查看行程时，竖屏更符合场景，且可以减少比赛现场不可控的布局分支。

必须遵守：

- 使用 `SafeArea` 或等价的系统 inset 处理刘海、状态栏和手势区；
- 底部导航和固定 CTA 不覆盖 Android 手势区域；
- 键盘弹出时使用 `resizeToAvoidBottomInset`，输入框与“生成”按钮不能被遮住；
- Android 返回键：详情页返回列表，规划页保留输入内容，生成中返回需给出取消或确认提示；
- 系统字体放大到 1.3 倍后，标题可以换行但不得裁切主要按钮；
- 不能通过 `textScaleFactor` 强行压回小字体；
- 图片和网络失败必须有固定尺寸占位，避免首屏跳动。

## 3. 全局尺寸 Token

不要在页面中继续散落任意数值。下一阶段统一为以下基线，个别内容型组件只能在注释中说明偏差原因。

```text
pageHorizontal       = 20dp       // S 也保留；极窄设备可降到 16dp
pageHorizontalSmall  = 16dp
sectionGap           = 24dp
contentGap           = 12dp
smallGap             = 8dp
cardRadius           = 4dp        // 河南编辑式视觉，不使用满屏胶囊
buttonHeight         = 48dp       // 主操作；小按钮不得低于 44dp
minTouchTarget       = 48dp       // 图标按钮也要有 48×48 的 hit area
bottomNavHeight      = 80dp       // 由 Material NavigationBar + system inset 决定
bodyFont             = 14sp
secondaryFont        = 12sp
captionFont          = 11sp       // 仅辅助信息，不放关键业务结论
pageTitle            = 24sp
sectionTitle         = 20sp
cardTitle            = 16sp
lineHeightBody       = 1.5
```

### 色彩状态不能只靠颜色

- 实时：图标/标签“实时数据”；
- 缓存：标签“缓存数据 · 更新于 xx:xx”；
- 演示：标签“演示数据”；
- 失败：错误图标 + 可读文本 + “重试”；
- 过期：警示图标 + “数据已过期”，不能只变成灰色。

## 4. 页面级布局规范

### 4.1 首页 / 发现

```text
SafeArea
└── CustomScrollView
    ├── 顶部品牌栏：左右内边距 20dp，高度约 48dp
    ├── Hero：宽度 = 屏幕 - 40dp，不固定屏幕宽；内边距 20–22dp
    ├── 主题走廊：横向列表，卡片宽度 276–292dp
    ├── 景点卡片：横向列表，宽度 228–244dp
    └── 决策支持卡：单列，自适应高度
```

在 360dp 上，页面可用内容宽度约 320dp；景点卡片不要超过 244dp，否则横向滚动的露出比例过小，用户看不出还有下一张。Hero 文案最多允许 3 行，输入框示例必须允许换行或省略，不得撑破卡片。

### 4.2 规划页

- 只保留一个主输入区域；自然语言输入使用 `maxLines: 4`，在 360dp 上仍能看到完整 CTA；
- 目的地 Chip 超过一行时使用 `Wrap`，不使用固定宽度 Row；
- 同行人数步进器的按钮命中区 48dp，数字不会因系统字体变大而溢出；
- 生成中显示阶段状态，而不是只把按钮文字改成“加载中”；
- 生成失败保留原始输入，显示错误编号和重试；
- 首次规划后显示结构化需求摘要，再进入结果，不用一个表单承载所有条件。

### 4.3 行程结果页

首版采用纵向单列，顶部保留标题、走廊、数据状态和核心指标；“行程 / 地图 / 预算 / 天气”使用同一上下文中的 peer tabs，不做底部一级导航。

- 时间轴的时间列在 S 档不超过 54dp；
- 节点正文使用 `Expanded`，长景点名允许两行；
- 费用、数据来源和风险提示不得使用固定横向 Row 强行挤压；必要时改为 Wrap 或纵向排列；
- 预算图在 360dp 上不小于 168dp 高，图例采用列表，不能只依赖扇区颜色；
- 风险说明永远在结果页可见，不藏在“更多”里；
- 调整结果必须显示“改了什么 / 预算变化 / 强度变化 / 撤销”。

### 4.4 景点详情

- 头图高度 240–280dp，使用固定比例而不是固定图片宽度；
- 标题和摘要使用内容驱动高度；
- “加入我的行程”作为底部安全区域内主操作，滚动查看时不被遮挡；
- 门票、时长、适合人群三项在 S 档允许换成两行网格；
- 数据来源、更新时间、预约说明在同一信息组内呈现。

### 4.5 今日行程

今日页要服务于“下一站是什么”，不是重复完整攻略：

- 当前节点视觉权重最高；
- 下一站、预计到达、天气、路线入口必须在首屏可见；
- 已完成节点弱化但仍保留文字，不用颜色作为唯一状态；
- 无定位权限时显示手动出发地，不弹死循环授权；
- 无网络时显示最后更新时间和缓存标识。

## 5. 响应式规则（用约束，不用设备名称）

```dart
final width = MediaQuery.sizeOf(context).width;
final horizontal = width < 375 ? 16.0 : 20.0;
final isWide = width >= 412;
```

推荐规则：

| 条件 | 行为 |
| --- | --- |
| `< 375dp` | 页面左右 16dp；内容卡少减小内边距，不缩小关键字体；统计信息允许换行 |
| `375–411dp` | 标准 20dp；采用 390dp 主视觉稿 |
| `>= 412dp` | 保持单列核心任务；可增加横向留白，但文本最大宽度建议 520dp |
| `>= 600dp` | 首版仍为单列；地图/预算未来可做双栏，不在当前阶段强行扩展 |

禁止：

- 用固定屏幕宽度计算卡片：`width: 390`；
- 用固定屏幕高度承载页面正文；
- 通过 `Transform.scale` 缩小整页来“适配”；
- 在 360dp 上把所有信息塞入一行；
- 让横向滚动成为完成主任务的唯一方式；
- 依赖 hover、长按或不可发现的手势。

## 6. 图片、字体和滚动性能

- 图片必须指定展示尺寸或宽高比，避免加载后布局跳动；
- 下一阶段从 `Image.network` 迁移到 `CachedNetworkImage`，错误态使用河南主题占位；
- 首屏主图可以预加载，景点横滑列表懒加载；
- 不把远程图片作为唯一内容，网络失败时仍展示标题、城市、主题、门票和更新时间；
- 当前未配置自定义字体时，不要在 `ThemeData` 中使用不存在的 `'sans'` 字体族；使用平台 sans fallback 或将授权字体放入 `assets/fonts` 并登记许可证；
- 长页面使用 `ListView`/`CustomScrollView`，避免一层层 `SingleChildScrollView` 嵌套；
- 图表和地图只在对应 Tab 首次打开时初始化，避免首页启动就加载全部能力。

## 7. 可访问性与触控验收

每个主流程至少检查：

- 主操作按钮的语义标签清楚，如“开始规划”“保存行程”“撤销调整”；
- 图标按钮有 `tooltip` 或语义标签，不能只有图形；
- 点击区域至少 48×48dp；
- 文字对比度达到 WCAG AA 方向，状态有图标/文字辅助；
- 系统字体 1.3 倍时不裁切、不重叠、不隐藏主操作；
- TalkBack 能读出景点名、数据状态和按钮作用；
- Android 返回键、系统分享取消、权限拒绝和网络失败都能恢复；
- reduced motion 场景不依赖动画传达唯一信息。

## 8. 设备矩阵与截图命名

比赛验收至少保留以下截图/录屏：

```text
01-home-360x800dp.png
02-home-390x844dp.png
03-home-412x915dp.png
04-planner-keyboard-390dp.png
05-plan-result-360dp.png
06-plan-result-390dp.png
07-detail-390dp.png

```

建议 Android 模拟器：

- API 29 或 API 35；
- 360×800dp portrait；
- 390×844dp portrait；
- 412×915dp portrait；
- 字体默认与 1.3 倍各一轮；
- 在线、弱网、断网、定位拒绝四种状态。

## 9. 本规范的验收门槛

下一阶段至少满足：

1. 三个宽度档位无水平溢出和 RenderFlex overflow；
2. 规划输入、键盘、生成按钮、错误提示都可操作；
3. 行程时间轴长标题、风险、来源在小屏可读；
4. 预算图和天气卡不使用静态尺寸破坏布局；
5. 所有图片失败有占位，网络失败有明确数据状态；
6. 关键流程不依赖登录、定位、地图或实时服务才能完成演示；
7. 截图与录屏统一以 390dp 主稿，360dp 作为底线证据。
