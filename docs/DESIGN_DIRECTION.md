# 《豫见智旅》视觉方向 v0.2：天地之中 · 行程是一条测量过的线

> 目标读者：设计与前端实现。
> 结论先行：v0.1 的“AI 味”不是错觉，可以逐条指认；v0.2 换一套**从河南材料里长出来**的视觉语言，
> 而不是继续调整同一套模板的配色。

## 1. 问题诊断：v0.1 命中了哪些生成式默认特征

| 生成式默认特征 | v0.1 的实际情况 |
| --- | --- |
| 暖米色底（≈#F4F1EA）+ 高对比衬线标题 + 陶土色强调（≈#D97757） | 底色 `#F7F4EC`、强调 `#B84A32`、衬线中文标题 + 金色“豫”字印章 |
| 用中点拼接元信息（A · B · C） | “郑州—洛阳 · 适中节奏 · 演示数据” |
| 统一圆角卡片堆叠，同一套浅描边 | 所有内容都装进 3–4px 圆角、1px 描边的等权容器 |
| 装饰性编号 01 / 02 / 03 | 规划页“01 先说说”“02 确认几个关键信息” |
| 与题材无关的模板装饰 | 印章方块、麦穗金、古风配色 |

单看每一条都算不上错，问题是它们**与题材无关地同时出现**：把题材换成“山西文旅”或“江南水乡”，
这套界面几乎不用改。这才是“AI 味”的来源。

## 2. 题材挖掘：什么既是河南独有，又能变成界面结构

放弃“古都 + 印章 + 山河”的第一反应，去找更具体、能直接转化成组件的材料：

- **汝瓷天青**（宝丰清凉寺）：河南名物。釉色是**冷调青绿**，开片（冰裂纹）本身就是一张细线网络。
  它给出一套非米色的冷基底，以及“细线”这个结构母题——而不是又一层装饰纹样。
- **天地之中与测影**（登封观星台）：河南在古代是“测出来的中心”。测量 = 轴线、刻度、数字，
  而行程规划的本质正是这三样。
- **龙门石窟的窟龛**：一面墙上成百上千个尺寸相近、拱顶的小龛。这是现成的**内容网格**隐喻：
  每个龛 = 一个景区。
- **列车运行图与时刻表**：郑州是路网十字。行程是一条带刻度的线，不是一摞卡片。

## 3. 设计方向

> **把行程画成一条测量过的线，把景区库画成一壁窟龛。**

“行程”不再由卡片承载，而是由**轴线 + 刻度**承载时间、距离、换乘；
“景区库”不再由横向圆角卡片轮播承载，而是由**两列窟龛网格**承载图像。
界面其余部分是纸与线，全局只有一处浓重。

### 3.1 色彩

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 釉白 | `#EFF1EE` | 页面底色。冷调，替换原来的宣纸米色 |
| 匣钵 | `#1B2422` | 主文字与深色面 |
| 天青 | `#3F6F6A` | 品牌与结构色（汝瓷釉色向内收的取值） |
| 天青淡 | `#C9D8D3` | 刻度线、分隔、未选中态 |
| 开片灰 | `#7C8B87` | 次级文字、单位 |
| 窑变朱 | `#A8341E` | **唯一强调色**：下一站、当前节点、必须注意的风险 |

使用纪律：**窑变朱在单屏内原则上只出现一次**。它是“你现在在这里”的标记，不是主题色。

### 3.2 字体

不引入新字体文件（CJK 字体体积与授权成本不划算，离线包也不该依赖网络字体）。
**特色由排版承担，而不是由字库承担**：

- 正文与标题同族（系统 CJK 无衬线），层级靠字号、字重与**对齐**拉开；
- 所有数字（时间、时长、价格、里程）启用 `FontFeature.tabularFigures()`，
  让刻度与金额成列对齐——这是“测量”语言的一部分；
- 数字承担视觉主角（`09:00`、`¥385`），文字退为标签；
- 取消“衬线中文大标题 + 金色印章”的模板组合。

### 3.3 版式

- 全部左对齐，不用居中标题；正文行宽受 `maxContentWidth` 约束。
- 分组靠**对齐与刻度间距**，不靠给每个区块加描边。
- 容器只在两种情况下出现：① 内容确实是独立单元（窟龛图块、行程节点）；
  ② 需要与背景分离的实时状态（下一站条）。其余一律用空白与细线分节。
- 圆角统一收到 2px，不再“万物 4px”。

### 3.4 原则

1. **可执行优先**：时间、距离、费用成列对齐，一眼能核对。
2. **一处浓重**：全局只有一个强调色、一个重色面。
3. **线即行程**：轴线与刻度承载行程，不用卡片堆叠。
4. **去元信息串**：不再用中点拼接；要么标签-值成对，要么交给刻度。
5. **图像只属于景区**：界面其余部分由纸与线构成。

## 4. 自查：新方向会不会又落进另一个默认

| 生成式默认特征 | 本方向的处理 |
| --- | --- |
| 暖米 + 衬线 + 陶土 | 已避开：冷釉白底、无衬线、单一朱点且单屏只出现一次 |
| 近黑 + 荧光强调 | 未采用 |
| **杂志式细线分栏 + 零圆角 + 密集排版** | **需要警惕**。本方向确实使用细线，区别在于这些线**编码测量**（刻度、序号间距、时间对齐），而不是充当分栏装饰；内容单位是窟龛图块，不是报纸栏。 |
| 同款圆角卡片 | 已移除：只在“独立单元”和“实时状态”两类场景保留容器 |
| 全大写眉标 / 中点元信息 / `→` 后缀 / 等宽小字标签 | 中点串已移除；`→` 只作为导航图标语义保留 |

保留细线，但把它牢牢绑定在“测量”语义上，这是本方向主动承担的风险。

## 5. 改动落点

落在：色彩 / 字体 / 间距 / 圆角 Token，导航与按钮形态，首页（英雄区 + 窟龛网格 + 走廊刻度带），
行程页（轴线刻度），今日页（下一站条），景区详情，规划页分步。

不做：引入网络字体、生成式图片素材、改动信息架构、改动任何业务流程。

## 6. 实现记录

### 6.1 已替换

| v0.1 | v0.2 |
| --- | --- |
| 宣纸米 `#F7F4EC` + 朱砂 `#B84A32` + 麦穗金 `#C69A52` | 釉白 `#EFF1EE` + 窑变朱 `#A8341E`（单屏一次） |
| 金色“豫”字印章方块 | 纯文字品牌锁定，无装饰 |
| 所有区块统一 3–4px 圆角描边卡片 | 细线分节；只有窟龛图块、下一站条与风险块保留容器 |
| 横向圆角景区卡片轮播 | 两列窟龛网格（拱顶裁切） |
| 时间轴圆点 + 卡片节点 | `RouteGauge` 测量轴线（时间右对齐、刻度、图标化单位） |
| 4 段饼图预算 | 比例测量条 + 等宽数字图例 |
| 元信息中点串（`A · B · C`） | `KeyValueRow` / `MeasureValue` / 图标单位 |
| 装饰性 01 / 02 编号 | 去掉；内容顺序本身表达步骤 |
| `auto_awesome`（AI 陈词滥调图标） | `timeline` / `route` / `explore` |

### 6.2 截图自评发现并修正的问题

用一次性的 golden 渲染（390×844）把三张关键页面画出来逐张检查，发现两个真问题：

1. **状态徽标重复。** 每个行程节点都带一枚「演示数据」，单屏红色出现四次以上，
   自己定的“一处浓重”被破坏。改为：整份方案已经声明过的来源，节点只有在**自己状态不同**时才重复。
2. **来源与状态混为一谈。** `PlanStop.source` 的默认值是 `演示数据`（那是状态不是来源），
   于是每个节点出现“演示数据 / 演示数据”两行。默认来源改为 `系统景点库`，并把单位标签写成「来源 …」。

另外把风险块的多余描边去掉（色块本身已足够分离），并把禁用态按钮从 `天青淡` 压到 `surfaceTint`，
避免禁用控件比可用控件更抢眼。

> 预览用的 golden 测试与图片是临时手段，已从仓库移除，不进入交付内容。

### 6.3 遗留

- `fl_chart` 目前在本 APK 中已无调用点（饼图被比例条取代）。要么在后续的可视化中继续使用，
  要么从 `pubspec.yaml` 与第三方声明中移除，不要长期留着一个未使用的依赖。
- 窟龛网格仍使用远程示例图，正式版本需替换为有授权的河南景区照片。
- 系统字体放大到 1.3 倍的实机表现仍未验证。

## 7. 待办（不在本次范围）

- 若要进一步强化“测量”语言，可考虑内置一款开源数字字体（仅拉丁与数字子集，体积可控），
  需要在 `THIRD_PARTY_NOTICES.md` 登记授权。
- 窟龛网格目前使用远程示例图，正式版本需替换为有授权的河南景区照片。

# v0.3 修订：方向改为"现代中原文化 × 山河旅行影像"

日期：2026-10-01（Asia/Shanghai）

v0.2 的**问题诊断**依然成立：v0.1 的"暖米 + 衬线 + 陶土 + 印章"确实是生成式默认。
被推翻的是 v0.2 为解决问题而选的**结构手段**。

## 保留

- 从河南具体材料取材（汝瓷天青、天地之中、龙门窟龛、铁路运行图）；
- 一套冷调基底，不用暖米色；
- "一处浓重"：单屏只有一个强调色、一个重色面；
- 不再用中点拼接元信息；
- 图像只属于景区。

## 推翻

| v0.2 主张 | 为什么推翻 |
| --- | --- |
| 零圆角、细线分节 | 竖屏拇指操作需要可点与不可点的边界；全直角让两者难以区分 |
| "线即行程"，轴线承载结构 | 把抽象层级选错了：每块都要用线表达关系，页面必然变成线框图 |
| 杂志式密集排版 + 窟龛网格 | 适合桌面/iPad，不适合 360dp 手机 |
| 关闭 `InkSparkle` | 直接导致"交互生硬" |

这正是 v0.2 文档第 4 节**自己预警过的风险**（"杂志式细线分栏 + 零圆角 + 密集排版"），
它确实发生了。记录的教训：自查表只有被当成验收条件才有意义。

## v0.3 的落点

- 影像优先：景区照片是第一信息载体；
- 圆角分组：`SurfaceCard` 18 / 控件 14 / 小件 10 / 胶囊 999；
- 行程用时间轴承载，预算用比例条承载；
- 恢复水波纹与按下缩放，交互必须有反馈；
- 指标与图片加载不引入"假装在动"的无限动画。

完整的配色、间距、组件与验证记录见 `docs/UI_REDESIGN.md` 的 v0.3 章节，
以那里为唯一实施真源。
